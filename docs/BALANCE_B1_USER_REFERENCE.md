# Geometry Defense — баланс волн 1–100
**Версия:** B1.0, 17.10.2026  · **Статус:** рассчитанный кандидат для реализации и симуляционного тестирования, НЕ подтверждённый игровой баланс.  · **Назначение:** Codex / Godot / Android.

> **Главное ограничение.** Исходники текущего APK и точные DPS, цены, размеры пути, скорость врагов и реальные HP старой версии не были доступны для численного аудита в этой задаче. Поэтому ниже — внутренне согласованный проектный баланс, основанный на согласованных правилах и статистике 49 волн, а не утверждение о точном балансе HexDefense. Перед выпуском APK Codex обязан сравнить его с фактическим кодом, симулировать несколько стратегий и откалибровать параметры. Ниже есть все 100 волн, явные формулы и критерии проверки.

## 1. Диагноз по реальному тестовому матчу
- По скриншотам: к волне 49 база имеет 1/10 HP; боссы на волнах 5–45 регулярно проходили (по одному на босс-волне). На 49-й волне убито 30 обычных врагов без утечки. Это системный разрыв между угрозой обычных волн и боссов, а не просто «сложная игра».
- Статистика: 1477 убийств, 235.0K суммарного урона, 1894 заработано, 1917 потрачено. Разница расходов и дохода −23 объяснима стартовым бюджетом, но точное стартовое значение по скриншоту не подтверждено.
- Лазер №1: 197.1K урона, 1280 убийств, 793 вложено; лазер №2: 21.0K / 116 / 377; лазер №3: 3385 / 18 / 115. Миниган №881: 378 / 4 / 88; №1160: 4259 / 17 / 130; №1161: 2994 / 22 / 130; ракета №1336: 5882 / 20 / 284. **Вывод:** первый лазер наносит около 84% общего зарегистрированного урона (197100/235000); это повод проверить попадания по линии, время присутствия на поле, перераспределение убийств и эффективность инвестиций, а не доказательство бага в каждой другой башне.
- По 49 волнам на скриншотах видно: обычные волны обычно проходятся без потерь, а потери HP в основном происходят на боссах. Нужно снизить HP боссов относительно прежней версии и одновременно сделать обычные волны менее тривиальными.
- **Проверка телеметрии:** 235.0K общего урона может включать overkill/поражение детей после разделения; Codex обязан различать `damage_attempted`, `damage_effective`, `overkill` и урон по боссам.

## 2. Подтверждённые правила (не менять без согласования)
- 4 башни: Minigun, Laser, Rocket, Shockwave. Улучшение одной веткой с 1-го по 10-й уровень; отдельная платная ульта; 3 секунды игрового времени на апгрейд/ульт, башня в этот период не стреляет; 5 секунд на слияние, обе башни не стреляют.
- 3 обычных типа: **квадрат** (обычный), **треугольник** (быстрый), **фиолетовый круг** (делится на два меньших, чуть более быстрых). Удалить из кода броню/тяжёлых и любые другие неутверждённые обычные типы. Боссы остаются.
- 4 босса, каждый иммунен к одному классу башен, циклически каждые 5 волн. Боссы и обычные враги снимают по **1 HP базы**, если дошли. Обычные враги не имеют классовых сопротивлений.
- Особые смешанные волны: 19, 39, 59, 79, 99. На них все 3 обычных типа в одной волне. У разделяющихся два ребёнка после уничтожения родителя.
- Волны 5, 10, …, 100 содержат одного босса **и** обычных врагов. Суммарный счёт убийств на волнах с разделением включает детей.
- Единый интервал выхода обычных врагов; дальнейшее сближение естественно из-за разных скоростей и деления. База 10 HP.
- Радиус Minigun от 1.25 до 4.00 расстояний между центрами соседних гексагонов; Rocket от 1.75 до 5.00. Laser без ульты имеет постоянный радиус, с ультой ×2; Shockwave растёт по уровням.
- В игре должна быть встроенная диагностика выбора целей, причин простоя, урона, иммунитетов, спавна, затрат и фактического радиуса.

## 3. Исследование: какие принципы использованы
1. **Не одна экспонента.** Сложность зависит от HP × количества × состава × скорости и доступного времени атаки; нельзя увеличивать все множители без проверки. Источник: [Wave Difficulty Ramp Guide](https://gamesdesign.co.uk/guides/tool-wave-difficulty-ramp-guide.html).
2. **DPS за единицу валюты и AoE.** Для лазера/волны учитывать среднее число поражённых целей, а не только урон по одной цели. Источник: [Balance Analysis & Normalization](https://github.com/djpav/threejs-tower-defense/blob/main/docs/BALANCE.md).
3. **Доход должен соответствовать стоимости следующего полезного улучшения**, а не расти бесконтрольно; резкие скачки сложности требуют целевого тестирования. Источник: [How to Balance a Tower Defense Game](https://playfoe.com/blog/how-to-balance-a-tower-defense-game).
4. **Нужна симуляция стратегий**, а не только красивые формулы. Источники: [TD Difficulty Lab](https://pointclair.itch.io/td-difficulty-lab), [Wave Balancing Tool](https://njsublett.itch.io/wavebalancingtool).
5. **Разделение награды за родителя и детей** необходимо, чтобы не создавать бесконечный фарм за один спавн. Это проектное решение, не заимствованная «официальная» цифра.

## 4. Числовая модель HP, скорости и наград
Все `round()` в этом документе означают округление **половины вверх** до целого, а не Python bankers rounding. Сначала вычислить базовый HP волны, затем коэффициент типа, потом округлить. Значения неизменны в пределах одной волны.

```text
wave = 1..100
H(w) = round(28 * 1.055^(w-1))              # базовое HP квадрата
HP_square(w)   = H(w)
HP_triangle(w) = round(0.70 * H(w))
HP_splitter(w) = round(1.20 * H(w))        # HP родителя
HP_child(w)    = round(0.35 * H(w))        # HP каждого из двух детей
HP_boss(w)     = round(7.50 * H(w))        # только w % 5 == 0
count(w)       = min(30, 7+w)             # 8 на 1-й, 30 начиная с 23-й
R(w)           = max(2, round(2 * 1.024^(w-1)))  # награда за квадрат/треугольник
R_parent(w)    = round(0.75 * R(w))
R_child(w)     = round(0.20 * R(w))       # каждому из двух детей
R_boss(w)      = round(18 + 0.95*w + 0.032*w*w)
B(w)           = round(4 + 0.6*w + 0.018*w*w) # бонус за завершённую волну
```
**Почему именно так:** 5.5% HP за волну создаёт умеренную экспоненту на 100 раундов; число врагов ограничено 30, чтобы не создавать бесконечный рост дохода и нагрузку на телефон. Награда за отдельного врага растёт медленнее HP; растущая премия за волну компенсирует это, чтобы игрок мог покупать поздние улучшения. Коэффициент босса 7.5× базового квадрата — **стартовая гипотеза**; без проверки DPS и длины маршрута не гарантирует победу. В отличие от старой версии босс должен быть тестируемым и убиваемым.

### 4.1 Скорость (относительно квадрата)
| Тип | Множитель скорости | Назначение |
|---|---:|---|
| Квадрат | 1.00× | Стандарт |
| Треугольник | 1.45× | Меньше HP, но меньше времени под огнём |
| Фиолетовый круг | 0.90× | Родитель медленнее, HP выше |
| Маленький круг | 1.15× | Два ребёнка после гибели родителя |
| Босс | 0.75× | Медленнее обычного, но иммунен к одному классу |

Не увеличивать скорость с номером волны без нового решения: иначе HP × скорость дают двойное усиление, а игра становится непрозрачной. Абсолютную скорость в пикселях/сек брать из фактической длины пути и желаемого времени прохода, а не из размеров экрана. Для детей HP и награда назначаются при появлении; **каждый** ребёнок при утечке снимает 1 HP.

### 4.2 Типы волн
- Обычные волны: тип по циклу квадрат → треугольник → делящийся, если волна не боссовая и не смешанная. Это **новая схема**, не претензия на оригинальную HexDefense; её можно заменить на расписание из кода после аудита.
- Боссовые волны: `count(w)` квадратов + 1 босс. Босс выходит последним после обычных врагов, чтобы башни могли переключиться на него; при тестах также проверить более ранний спавн.
- Смешанные: ровно 30 исходных врагов, поровну 10 квадратов + 10 треугольников + 10 делящихся (итого до 50 уничтожений с учётом детей). Не делать новые типы.
- В волнах с делящимися уничтожение всех 30 родителей и 60 детей даст до 90 убийств. Награды начисляются за каждое реально уничтоженное существо, по соответствующей таблице.

### 4.3 Важное правило экономики и утечек
- Валюта начисляется только за уничтожение конкретного врага. Утёкший враг не платит награду. Если родитель делится, награда за него выдаётся один раз; за каждого убитого ребёнка — отдельно.
- Бонус `B(w)` начисляется один раз при завершении волны, **даже если кто-то утёк**, если база выжила. Если база погибла, состояние откатывается к последнему завершённому сохранению; бонус не дублируется.
- При иммунитете босса соответствующая башня не наносит урон, но другие три класса могут атаковать. Боссовая награда начисляется только за убийство.

### 6.1 Что именно означает «максимальный доход»
Это **верхняя граница при убийстве всех**, а не гарантированный доход игрока. Если противник утёк, соответствующая награда не начисляется. В боссовой волне доход без убийства босса меньше на `R_boss(w)`. В волне деления убийство родителя, но пропуск детей уменьшает доход на `2*R_child(w)` на одного родителя.

## 8. Баланс DPS: без этого таблица HP не станет играбельной
Фактические характеристики 10 уровней каждой башни **не представлены** в доступных материалах. Поэтому не стоит выдавать произвольные числа урона за окончательно сбалансированные. Codex должен выгрузить из текущих скриптов `damage`, `shots_per_second`, `volley_count`, `range`, `splash_radius`, `targeting`, `projectile_speed`, `penetration`, `cooldown`, `upgrade_cost` для каждого уровня и сделать симулятор.

### 8.1 Эффективный DPS
```text
Minigun_raw_DPS = damage_per_bullet * bullets_per_second
Laser_raw_DPS   = damage_per_hit * pulses_per_second
Rocket_raw_DPS  = damage_per_rocket * rockets_per_volley * volleys_per_second
Shockwave_raw_DPS = damage_per_pulse * pulses_per_second
Laser_effective_DPS = Laser_raw_DPS * mean_enemies_intersected_per_beam
Shockwave_effective_DPS = Shockwave_raw_DPS * mean_enemies_hit_per_pulse
Rocket_effective_DPS = Rocket_raw_DPS * actual_hit_fraction
Boss_eligible_DPS = sum(effective_single_target_DPS of towers not blocked by immunity)
```
`effective_DPS` должен использовать **фактические попадания**, а не теоретические, чтобы не завышать пользу Rocket, если ракеты долго летят, и не занижать Laser, если он пробивает много целей.

### 8.2 Контрольные целевые диапазоны
- Волны 1–10: разумная сборка с разными башнями должна стабильно убивать обычных врагов, но не обязательно прямо на входе. Босс на 5-й волне должен быть победим при грамотном выборе 2–3 разных башен.
- Волны 11–30: большинство обычных врагов должно проходить заметную часть маршрута (ориентир 25–65% длины пути), а не умирать на первой клетке; хорошо оптимизированная оборона может убивать раньше.
- Волны 31–60: для смешанных волн и боссов требуются улучшения и разнообразие классов; игрок не должен проигрывать только из-за иммунитета к единственной башне при разумной стратегии.
- Волны 61–100: нужна осмысленная расстановка и использование ульт/слияния. Прохождение 100-й волны возможно при хорошей стратегии, но не гарантировано для случайной расстановки.
- Цель по боссам при **подходящей сборке**: босс погибает в пределах последних 15–75% доступного пути (не сразу у входа и не неизбежно на выходе). Измерять по нормализованному прогрессу пути.
- Тестировать стратегии минимум: преимущественно Minigun, преимущественно Laser, преимущественно Rocket, преимущественно Shockwave, смешанная сбалансированная, ранние апгрейды, раннее расширение, экономная игра, стратегия с ультами и слияниями.

### 8.3 Отдельный тест боссов
Для каждого босса записать: HP, иммунитет, общее время под огнём, допустимый DPS, фактически полученный урон, сколько времени и клеток оставалось до базы при смерти/утечке. Если босс регулярно доходит с более чем 20% HP при разумной сборке — снизить коэффициент `7.5` или исправить target acquisition/простои. Если умирает до 10% маршрута — увеличить HP или исправить ошибочно многократное применение урона. Не подгонять баланс, пока логика атаки неисправна.

## 9. Встроенная диагностика и балансировочный симулятор
Включить `debug_balance_mode` и экспорт `balance_report.json`/`balance_report.csv` после матча. Писать не каждую пулю в постоянный лог, а агрегировать события, с выборочным подробным трейсом по проблемным башням.

**Для каждой башни:** ID, класс, уровень, стоимость, местоположение, время постройки, радиус в клетках, выбранная цель, секунды с целью в радиусе, секунды без цели, секунды простоя при наличии доступной цели, причина нестрельбы (`upgrading`, `no_target`, `cooldown`, `line_of_sight`, `paused`, `invalid_target`, `projectile_limit`, `other`), выстрелы, попадания, промахи, эффективный урон, overkill, убийства, вклад в боссов, средний DPS, стоимость за единицу урона.

**Для каждого врага/босса:** ID, волна, тип, стартовое HP, итоговый урон по источникам, иммунитет, число полученных попаданий, точка смерти/утечки, сколько HP оставалось при утечке, скорость, путь. Для делящихся — ID родителя и детей.

**Для каждой волны:** состав, исходный count, реальное число детей, время, получено/потрачено, баланс валюты до/после, общий HP пул, нанесённый эффективный урон, утечки, состояние базы, номер самой результативной башни, длительность простоя башен, средний прогресс пути до смерти врага.

**Автоматические тревоги:**
- Башня с целью в радиусе не стреляет дольше 2 своих штатных интервалов атаки, если не на апгрейде и не на паузе.
- `effective_damage > enemy_remaining_HP` без отдельного учёта overkill.
- Урон босса от иммунного класса > 0.
- HP/награда/число спавнов расходятся с таблицей текущей волны.
- Больше одной выплаты за одну смерть; двойная выплата бонуса за волну.
- Враг убит вне фактического радиуса башни или Laser пересёк врага без попадания.
- Босс 3 раза подряд прошёл с >20% HP; 80%+ обычных врагов умирают в первых 15% пути пять волн подряд.
- `tower_idle_while_target_in_range_seconds > threshold` для Shockwave или любой другой башни.

4. Запустить автоматические матчи 1–100 на скорости симуляции без графики для минимум 10 стратегий, сохранить JSON/CSV.
5. Для каждой волны вывести `wave_total_HP`, `effective_tower_DPS`, `income`, `upgrade_spend`, `leaks`, `boss_remaining_HP_at_exit`, `median_enemy_death_path_fraction`.

## 13. Псевдокод генератора и контракт интеграции
```python
from math import floor
def r(x): return floor(x + 0.5)
def wave_config(w):
    assert 1 <= w <= 100
    h = r(28 * (1.055 ** (w - 1)))
    n = min(30, 7 + w)
    reward = max(2, r(2 * (1.024 ** (w - 1))))
    bonus = r(4 + 0.6*w + 0.018*w*w)
    if w % 20 == 19:
        groups = {"square": n-n//3-n//3, "triangle": n//3, "splitter": n//3}
    elif w % 5 == 0:
        groups = {"square": n, "boss": 1}
    else:
        groups = {("square", "triangle", "splitter")[(w-1)%3]: n}
    return {"wave": w, "groups": groups, "hp": {
        "square": h, "triangle": r(.7*h), "splitter": r(1.2*h),
        "child": r(.35*h), "boss": r(7.5*h)},
        "reward": {"square": reward, "triangle": reward,
        "splitter": r(.75*reward), "child": r(.20*reward),
        "boss": r(18+.95*w+.032*w*w)}, "completion_bonus": bonus}
```
